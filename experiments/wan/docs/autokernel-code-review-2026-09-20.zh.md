## 影响实验结论的问题

| 高 | **未回接也能报已替换。** 模型回接仅支持三类算子，但报告按“加载成功”计数；flash_attention 可实际替换 0 个，却报告 1 个。 | [verify.py](../../../verify.py)，532、557–573、1222 行 |

## 按五项标准看

- **算清上限：**有 FLOPs 和字节量公式，硬件参照需要核实。
- **找到瓶颈：**模型分析主要按算子类型打标签；未发现标准流程内的 NCU 硬件指标采集与决策链。宿主 Agent 仍可能自行调用，需看运行轨迹。
- **有据修改：**手册要求先写假设、每次单项修改、记录与回滚；执行质量仍依赖宿主 Agent。
- **验证结果：**已有精度与性能检查，但上面的权重、回接和状态汇总问题会影响判定。
- **合理停止：**已有预算、停滞和峰值规则，数据传递与计时实现需要重点核验。

**复现重点：参数是否一致、候选是否真正执行、诊断是否来自实测、停止理由是否成立。** 原生失败照实保留，Codex 不替框架修实现。

验证范围：相关源码与冻结上游一致；完成 CPU 控制流模拟，未新增 GPU 实验。模拟证明代码路径，不能代替 B300 运行结果。可核对的触发条件和模拟结果见[审查证据](autokernel-code-review-evidence-2026-09-20.json)。
