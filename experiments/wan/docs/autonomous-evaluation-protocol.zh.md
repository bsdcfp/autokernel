# 算子优化 Agent 评测协议

v2 · 2026-09-20

## 目标

通过开源框架和 B300 上的 Wan 实验，讲清楚算子优化 Agent 的原理、架构与设计模式。既看算子能快多少，也看 Agent 是否知道为什么快、还能怎样优化。

## 怎么测

先复现官方示例，确认用法正确，再迁移到 Wan。固定任务、精度要求、硬件和预算，让框架自主完成一次优化；Codex 只负责环境、记录和最终独立验收。

## 看哪五件事

| 能力 | 要看到的证据 |
|---|---|
| 算清上限 | 计算量、访存量与对应硬件上限 |
| 找到瓶颈 | Agent 自行取得 NCU 或等效数据，说明卡在哪里 |
| 有据修改 | 修改针对什么瓶颈，预计哪个指标会改善 |
| 验证结果 | 精度通过；相对默认 torch.compile 的加速；前后指标是否支持解释 |
| 合理停止 | 为什么继续、回滚或停止；还剩多少空间，不知道就写不知道 |

## 判定原则

- 只有加速，不能证明诊断正确；预算用完，不等于达到极限。
- 证据必须来自 Agent 自己的运行过程。Codex 事后补做，不计为框架能力。
- 原生配置和增加提示、工具或反馈后的配置分开比较。
- 每项标明：未做、证据不足、有证据、已用于决策。失败、工具受阻和记录缺失如实保留。
- 同时报耗时、调用成本和人工介入；一次成功不代表稳定成功率。

最终报告回答：**做对了吗？快了多少？为什么？还能快吗？花了多少代价？这些是否由 Agent 自主完成？**
